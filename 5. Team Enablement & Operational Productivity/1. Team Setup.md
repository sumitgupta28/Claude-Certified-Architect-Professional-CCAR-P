## 1. Summary: Key CCAR-P Architectural Takeaways

Screen 2 distinguishes between the **4 Skill Distribution Mechanisms** and the separate channel for **Centrally Managed Claude Code Configuration**.

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                 SKILL DISTRIBUTION VS. SETTINGS MECHANISMS                  │
├─────────────────────────────────────────────────────────────────────────────┤
│ SKILL DISTRIBUTION PATHS:                                                   │
│ 1. Org-Provisioned Skill ──► Org-wide reach | Manual re-upload (No version   │
│                              pinning or native rollback)                    │
│ 2. Group/Org Plugin      ──► Targeted rollout | Install preferences:        │
│                              Required, Installed by default, Available      │
│ 3. Project-Scoped Skill  ──► Scoped to repo/project files                   │
│ 4. API Skill             ──► Programmatic calls by partner products         │
├─────────────────────────────────────────────────────────────────────────────┤
│ SEPARATE SETTINGS CHANNEL:                                                  │
│ • Centrally Managed Claude Code Configuration                               │
│   └── Delivered via Anthropic servers upon authentication                   │
│   └── Refreshed on an HOURLY POLLING CYCLE                                  │
│   └── NOT a Skills distribution path                                        │
└─────────────────────────────────────────────────────────────────────────────┘

```

### Core Architectural Pillars for CCAR-P:

* **Org-Provisioned Skills (Org Settings > Skills)**: Best for capabilities that must reach *everyone* across the enterprise. Managed by owners across the organization. Users can toggle individual skills off but cannot delete them. **Crucial Governance Limit**: They lack native version pinning and native rollback; updates require manual re-upload.
* **Plugins Assigned to a Group / Org**: Ideal for capabilities requiring **governed rollouts** or **group targeting** (specific teams/roles). Administrative UI supports granular install preferences:
* *Required* (Mandatory enforcement)
* *Installed by default* (Pre-configured but user-modifiable)
* *Available to users* (Self-service catalog)


* **Project-Scoped & API Skills**:
* *Project-Scoped Skills*: Reside inside the code repository itself and carry project-specific context.
* *API Skills*: Invoked programmatically by custom enterprise software products.


* **Centrally Managed Claude Code Configuration**: Delivered directly from Anthropic's servers when users authenticate, and updated automatically via an **hourly polling cycle**. This is strictly a settings and environment management channel, **not** a distribution path for Skills.

## 2. Clear & Simple Explanation

1. **Broad Broadcast vs. Targeted Delivery**:
* Think of **Org-Provisioned Skills** as baseline radio broadcasts sent to all employees (e.g., standard code formatters). Everyone gets them, but if you make a mistake, you can't hit "undo"—you must re-upload the corrected file manually.
* Think of **Plugins** as targeted software assignments sent to specific departments (e.g., specialized security tools for the SecOps team). You can choose whether a plugin is mandatory (*Required*), pre-installed (*Installed by default*), or optional (*Available*).


2. **Settings vs. Skills**:
* **Skills** give Claude new capabilities or workflows.
* **Claude Code Configuration** sets system preferences (like API limits or developer rules). Configurations run on a separate server channel that automatically syncs every hour (**hourly polling cycle**), completely independent of how Skills are distributed.

## 3. Real-World Application Scenario

### Enterprise Scenario: Regulated Banking Platform Tooling Strategy

An enterprise financial institution configures Claude developer tooling across 300 engineers spanning Core Banking, Mobile Frontend, and Security Operations teams.

```
                                [ ENTERPRISE DISTRIBUTION ]
                                             │
      ┌──────────────────────────────────────┼──────────────────────────────────────┐
      │                                      │                                      │
      ▼                                      ▼                                      ▼
[ ORG-PROVISIONED SKILL ]            [ GROUP-ASSIGNED PLUGIN ]           [ SERVER CONFIG CHANNEL ]
• Global Org Reach                   • Mobile Devs: Default              • Central Claude Code Config
• Standard Security Policy           • SecOps: REQUIRED                  • Delivered on Auth
• Manual Re-upload on update         • Group-targeted rollout            • Hourly Polling Refresh

```

1. **Global Mandates (Org-Provisioned)**: The architect deploys an *Org-Provisioned Skill* containing baseline corporate coding and privacy guidelines to all 300 developers. While developers can temporarily toggle it off in their local UI, they cannot delete it.
2. **Role-Specific Workflows (Group-Assigned Plugins)**:
* The *SecOps team* receives a specialized static-analysis plugin set as **Required**.
* The *Mobile Frontend team* receives UI testing tools set as **Installed by default**.
* Experimental beta tools are published to the internal catalog set as **Available**.


3. **Environment Sync (Central Config)**: Central IT manages developer guardrails and CLI settings via *Centrally Managed Claude Code Configurations*. When developers authenticate, these settings download automatically from Anthropic servers and refresh every hour without needing manual git pulls or Skill re-uploads.

## Key Technical Terms

* **Org-Provisioned Skill**: A globally available capability deployed via Organization Settings that reaches all users in an enterprise, lacking native version pinning or rollback capabilities.
* **Plugin Assigned to Group/Org**: A targeted packaging and distribution mechanism allowing administrators to deploy tool sets to specific teams with governance controls.
* **Install Preferences**: Administrative controls defining whether a group plugin is *Required* (mandatory), *Installed by default* (pre-configured), or *Available to users* (optional).
* **Project-Scoped Skill**: A Skill file residing directly within a project repository, bound to that specific codebase context.
* **API Skill**: A capability designed to be called programmatically by custom external software applications.
* **Centrally Managed Claude Code Configuration**: A server-side administrative mechanism that pushes system preferences and settings to Claude Code users upon authentication.
* **Hourly Polling Cycle**: The background refresh frequency used by Claude Code to check Anthropic's servers for updated system settings and configurations.
