### 1. Summary

The [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) module establishes the foundational architectural decisions required when translating unstructured business requests into enterprise-grade system architectures:

* **Decomposition & Responsibility Allocation:** System capabilities must be systematically assigned across Claude, existing deterministic systems, and human-in-the-loop controls using the **four properties of generative AI** as a decision lens. Over-assigning deterministic logic to Claude is identified as the most common early architectural failure.
* **Execution Pattern Selection:** Architects must evaluate system shapes across a spectrum—**augmented calls**, structured **workflows**, and autonomous **agents**—by balancing operational flexibility against non-determinism, latency, and **fan-out drop**.
* **State vs. Retrieval Separation:** Blueprint selection requires distinguishing static context from live operational data, preventing antipatterns where vector **retrieval** attempts to manage **live transactional state**.
* **Governance, Entry Points, & Stage-Gates:** System delivery routes (**Claude.ai**, API/SDKs, **Claude Code**, or **MCP servers**) must be filtered by enterprise governance and regulated-industry constraints before cost or latency trade-offs are evaluated. Model tier swaps (e.g., Sonnet to Haiku) require empirical validation through **evaluation stage-gates**.

### 2. Clear & Simple Explanation

* **Decomposition (Who Does What?):** Do not force Claude to do work that traditional databases or code handle perfectly. Assign deterministic tasks (like calculations or exact database lookups) to existing software, non-deterministic reasoning tasks to Claude, and high-risk decisions to human reviewers.
  
* **Pattern Selection (Execution Structure):** An *augmented call* is a simple input-output request. A *workflow* follows strict, step-by-step code paths with Claude handling specific nodes. An *agent* decides its own steps and tool usage dynamically. More autonomy brings higher flexibility, but also increases non-determinism and failure points.

```
A single augmented call (or a tool-augmented LLM call) in Claude's architecture is a foundational design pattern where Claude makes one single model request that is enhanced with external capabilities like functions, tools, retrieval data (RAG), or memory.

Core Characteristics

Single Turn: It executes in one model turn rather than a multi-step autonomous loop.
Integrated Data: External context (such as retrieved database chunks or API results) is injected directly into the prompt or handled via immediate tool execution.
Predictable Execution: Offers straightforward error handling, lower latency, and fixed cost compared to multi-agent or iterative looping agents.
```
  
* **State vs. Retrieval (Data Ownership):** Vector databases and RAG pipelines are meant for searching historical knowledge bases. They should never be used to keep track of real-time account balances or live inventory—that job belongs strictly to transactional databases.
  
* **Governance & Stage-Gates (Deployment Rules):** Security and regulatory rules must instantly rule out non-compliant deployment paths before you look at price or performance. Furthermore, never switch model tiers in production to save money without running automated test evaluations first to prove accuracy will not drop.

### 3. Preserve Technical Accuracy

Architectural decisions require precise technical differentiation across platform primitives and delivery routes:

* **Four Properties of Generative AI Lens:** Used during decomposition to audit capabilities, preventing deterministic drift where non-deterministic LLM calls replace proven algorithmic logic.
* **Pattern Spectrum & Fan-Out Drop:** Progression from single-completion calls to orchestrated multi-agent topologies, where architects must explicitly calculate and mitigate cumulative failure rates across parallel agent executions (fan-out drop).
* **Live Transactional State vs. Vector Retrieval:** Operational mandate ensuring ACID-compliant relational or key-value stores handle real-time transactional data, reserving RAG vector stores exclusively for unstructured context retrieval.
* **Model Context Protocol (MCP) Server Integration:** Standardized client-server protocol defining secure tool interfaces and context boundary delivery to Claude endpoints.
* **Evaluation Stage-Gate:** Mandatory benchmark evaluation suites executed prior to model tier downgrades, prompt restructuring, or context strategy alterations in production environments.

### 4. Real-World Application

An enterprise health insurance provider is designing an automated patient pre-authorization system:

* **Decomposition:** Patient eligibility and policy verification are routed to legacy core databases (**live transactional state**). Claude parses unstructured clinical notes submitted by physicians to identify requested medical procedures. Complex or ambiguous medical cases are routed to a nurse reviewer (**human-in-the-loop**).
* **Pattern & Architecture:** The team selects a structured **workflow pattern** over an autonomous agent to guarantee deterministic execution paths required for healthcare compliance audits.
* **Entry Point & Governance:** The solution connects through an **MCP server** integrated into private microservices via API SDKs over dedicated enterprise VPC endpoints. Direct web entry points (`Claude.ai`) and developer build interfaces (`Claude Code`) are explicitly ruled out upfront due to HIPAA data residency constraints.
* **Model & Evaluation Strategy:** The system initially uses Claude 3.5 Sonnet for clinical reasoning. To lower operating costs, the team evaluates migrating initial request classification to Claude 3.5 Haiku. Before deploying, the architecture passes through an **evaluation stage-gate** across 2,000 historical patient charts, confirming zero accuracy loss in procedure extraction before approval.

### Key Technical Terms

* **Decomposition:** The systematic partitioning of application requirements between Claude, deterministic legacy software, and human oversight based on capability fit.
* **Augmented Call:** A single-turn API completion where Claude transforms, classifies, or summarizes input using fixed context.
* **Workflow:** A structured execution pattern with hardcoded programmatic routing logic connecting discrete processing steps.
* **Agent:** An autonomous execution pattern where Claude dynamically determines task planning, tool selection, and multi-step execution.
* **Fan-Out Drop:** The cumulative drop in overall system reliability that occurs when multiple non-deterministic agent steps run in parallel or sequence.
* **Live Transactional State:** Real-time operational data requiring strict ACID compliance, managed by traditional database systems rather than vector search corpora.
* **Model Context Protocol (MCP) Server:** An open protocol enabling standardized, secure client-server integrations between Claude and external data sources or tools.
* **Evaluation Stage-Gate:** An automated testing workflow using standardized benchmark datasets to validate accuracy before deploying model or prompt changes.
* **Deterministic Drift:** The architectural failure caused by replacing reliable, rule-based algorithmic code with non-deterministic LLM completions.
