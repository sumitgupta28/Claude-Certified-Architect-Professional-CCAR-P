## 1. Summary: Reference Architectures & Pattern Selection

This module section of the [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) path details enterprise reference architectures—proven, adaptable shapes for wiring LLM applications—and their associated failure modes.

### Core Architectural Patterns

| Reference Architecture | Best Use Case / What Good Looks Like | Common Failure Mode / What Goes Wrong |
| --- | --- | --- |
| **Agent** | Workflows with non-deterministic paths (e.g., codebase investigation, research). Guided by scoped tools, tool permissions, and explicit **turn budgets**. | **Unbounded Autonomy**: Granting state-changing tools without turn limits, goal metrics, or human review gates. |
| **Retrieval-Augmented Generation (RAG)** | Question answering over stable, static knowledge corpora (e.g., product manuals, regulatory text, policy docs). | **Retrieval Applied to Live State**: Querying a cached snapshot index for fast-changing data (order status, inventory), yielding stale but confident answers. |
| **Document Processing (Evaluator-Optimizer)** | Field extraction from semi-structured documents (claims, invoices) against a strict schema with automated validation. | **No Exception Path**: Routing low-confidence extractions through standard processing without a **Human-in-the-Loop (HITL) gate**. |
| **Customer Service / Ticket Triage (Routing)** | Intent classification driving traffic to distinct backends: RAG for static docs, direct **Tool Calls / Transactional APIs** for live state, and human escalation. | Using retrieval for live order status; missing human escalation pathways; deploying agentic workflows before measuring simpler routed baselines. |
| **Coding Agent** | Hybrid pattern: Agentic multi-turn exploration phase paired with deterministic edit, test, propose, and review pipeline phases using isolated subagents. | Un-gated commits without human review; failing to track framework regression rates against designated **evaluation contracts (eval sets)**. |

---

### Key Architectural Takeaways

* **RAG vs. Tool Call Boundary:** The most critical failure mode in enterprise design is applying retrieval to **live state**. If data changes continuously, bypass the vector index snapshot and call live transactional APIs directly via tool use.
* **Composition Cost & Complexity:** Combining reference architectures (e.g., Routing + Agent + Evaluator-Optimizer) roughly doubles maintenance surface area. Each component requires its own independent **evaluation set (eval contract)** rather than relying on a single top-level system evaluation metric.
* **Governance & Escalation:** Automated workflows must incorporate defined fallback routes and exception pathways when model confidence drops or actions are high-consequence / state-changing.

## 2. Clear & Simple Explanation

Think of reference architectures as proven **building blueprints** rather than rigid rules:

* **RAG is like a library reference desk:** It works great when looking up books or static manuals. But if you want to know if a store item is in stock *right now*, looking at last week's printed catalog (a snapshot index) will give you wrong answers. You need to call the warehouse directly (**Tool Call / Live API**).
* **Routing is like hospital triage:** When a patient arrives, the triage nurse determines whether they need quick paperwork advice (RAG), a prescription update (API Tool Call), or immediate surgery (Human Escalation).
* **Coding Agents are detective work followed by assembly-line construction:** Searching for bugs in a complex system requires flexible, open-ended investigation (Agentic). But writing code, running unit tests, and submitting a pull request must follow strict, step-by-step checklists (Deterministic).
* **Composition Warning:** Combining two patterns is like building a hybrid car with both a gas engine and an electric engine. It offers flexibility, but doubles your maintenance work and requires two separate diagnostics toolkits (**Eval Sets**).

## 3. Real-World Application Scenario

### Enterprise Omnichannel Customer Support & Order Management System

* **Business Context:** A global retailer processes 200,000 daily customer interactions spanning product inquiries, return policy questions, live order tracking, address changes, and order cancellations.
* **Architectural Design:**
  1. **Intent Classifier / Routing Layer:** An initial fast classification call routes inbound user prompts to three distinct backend pipelines based on intent.
  2. **Static Knowledge Path (RAG Pipeline):** Questions about return policies, sizing charts, or store hours are routed to a RAG pipeline querying a vector database of indexed documentation.
  3. **Live State & Transaction Path (API Tool Calls):** Inquiries about order status, delivery tracking, or stock availability bypass vector retrieval entirely. The model invokes authenticated REST tool calls against the core PostgreSQL transactional database and shipping provider APIs to fetch live status.
  4. **State-Changing / High-Consequence Path (HITL Gate):** Requests to modify shipping addresses, cancel orders, or issue refunds above $50 trigger a structured payload routed to a human agent dashboard for single-click authorization.
  5. **Evaluator-Optimizer Exception Path:** If confidence scores for unstructured document uploads (e.g., scanned return receipts) fall below 85%, the job is routed to an exception queue for manual human inspection rather than committing raw extracted data.

## 4. Key Technical Terms

* **Reference Architecture:** A standardized, documented structural pattern for assembling system components to solve a recurring class of software or AI problem.
* **Retrieval-Augmented Generation (RAG):** An architecture where a static knowledge corpus is chunked, indexed, and retrieved as ground-truth context for model generation.
* **Live State:** Real-time operational data (e.g., stock levels, account balances, shipment status) that changes continuously and cannot be reliably served via a cached index.
* **Tool Call / Transactional API Integration:** The mechanism by which an LLM directly interacts with live backend services, databases, or external APIs to read real-time state or execute state-changing operations.
* **Unbounded Autonomy:** An architectural anti-pattern where an agent is granted state-changing tools without turn limits, guardrails, or human review gates.
* **Turn Budget:** A hard limit on the maximum number of interaction turns or tool calls an autonomous agent is permitted to execute for a single request.
* **Routing Architecture:** A pattern where an initial classifier evaluates user input and routes the request to specialized backends or workflows.
* **Evaluator-Optimizer:** An iterative pipeline pattern where a secondary model or deterministic process evaluates output quality against a schema or benchmark and requests corrections.
* **Evaluation Contract (Eval Set):** A benchmark dataset and measurement harness used to evaluate the correctness, latency, and regression rates of a specific architectural component.
* **Human-in-the-Loop (HITL) Gate:** A designated approval pause point in an automated workflow where human review is required before executing state-changing or high-consequence operations.

## 5. CCAR-P Practice Exam

### Question 1

A financial platform uses Claude to assist customer support representatives. Users frequently ask about live stock portfolio balances, historical performance, and investment firm terms of service. The team currently routes all queries through a single RAG pipeline over a vector database indexed daily at midnight. Customers report that portfolio balances provided by the assistant frequently contradict their online account dashboards. Which architectural modification should the Principal Architect implement?

A) Increase the vector embedding resolution and switch to hybrid lexical-semantic search.

B) Reduce the vector index refresh interval from 24 hours to 1 hour.

C) Refactor the architecture to route portfolio balance queries directly to live database APIs via Tool Calls, reserving RAG for static terms of service documentation.

D) Wrap the RAG output in an Evaluator-Optimizer loop to cross-reference output text with user chat history.

---

### Question 2

An enterprise software team is designing an autonomous coding agent with Claude to refactor legacy Java microservices. Which architectural design aligns best with Anthropic reference architecture guidelines to prevent regressions while maintaining exploration capabilities?

A) Allow the agent full autonomy to edit, compile, and commit code directly to the main repository until unit tests pass without turn limits.

B) Separate the workload into an agentic codebase exploration phase, followed by deterministic parse/plan/propose/test steps with a Human-in-the-Loop review gate prior to committing.

C) Replace the coding agent with a static RAG pipeline indexing all Java source code files.

D) Use a single prompt turn containing the entire microservice codebase to avoid subagent decomposition.

### Question 3

An architect is designing a composite solution that combines a Routing architecture, a multi-agent investigation loop, and a document processing pipeline. When establishing the quality assurance and monitoring strategy for production, which approach is required according to CCAR-P architectural guidelines?

A) Rely on a single end-to-end user satisfaction score to monitor all sub-components.

B) Implement separate evaluation sets (eval contracts) for each individual reference architecture within the system.

C) Disable telemetry logging across sub-components to minimize API latency.

D) Convert all sub-components into a single unified agent loop to share one evaluation harness.

### Question 4

A insurance provider implements an automated claims processing pipeline using Claude to extract structured fields from PDF damage reports. During peak load, low-confidence extractions on corrupted documents write invalid fields directly into the claims system. Which architectural component was omitted from this design?

A) A vector database index for claim forms.

B) A deterministic turn budget limit.

C) An exception path with a Human-in-the-Loop gate for low-confidence outputs.

D) A reciprocal rank fusion retrieval layer.

---

### Answer Key & Explanations

#### Question 1

* **Correct Answer:** **C**
* **Explanation:** Portfolio balances represent **live state**, which changes continuously. Using RAG over a cached vector snapshot (even refreshed hourly) is an anti-pattern that yields stale but confident answers. The correct architectural boundary is to route live state queries to transactional APIs via **Tool Calls** and reserve RAG for static knowledge (terms of service).

#### Question 2

* **Correct Answer:** **B**
* **Explanation:** A coding agent reference architecture separates work into two phases: **agentic exploration** (unpredictable navigation through code) and **deterministic execution steps** (parse, plan, propose, test, review) with a **Human-in-the-Loop gate** before state-changing actions like committing code. Unbounded autonomy (Option A) leads to uncontrolled regressions.

#### Question 3

* **Correct Answer:** **B**
* **Explanation:** Composing multiple reference architectures requires separate **eval contracts** for each architecture component. A top-level evaluation metric can mask critical failures occurring within underlying sub-components.

#### Question 4

* **Correct Answer:** **C**
* **Explanation:** Document processing pipelines must include an **exception path**. When extraction confidence falls below a target threshold or validation against the schema fails, low-confidence items must be gated for human review rather than written directly to production databases.
