### 1. Summary

The [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) module establishes the **Seven AI Primitives** as the foundational building blocks for assembling all higher-level Claude solution patterns (augmented calls, workflows, and agents):

* **Tools (Act):** Functions allowing the model to execute code or fetch external state.
* **MCP (Connect):** A standardized protocol for exposing reusable tool sets across multiple Claude entry points.
* **Subagents (Isolate / Parallelize):** Scoped instances assigned sub-tasks to run in isolated context windows or in parallel.
* **Hooks (Guarantee):** Event-driven, deterministic code blocks enforcing rules that the model cannot bypass.
* **Skills (Package a Procedure):** Reusable, versioned packages combining instructions and optional scripts for repeatable procedures.
* **Agent Teams (Coordinate Peers):** Multiple peer agents working in a coordinated topology toward a shared objective.
* **Dynamic Workflows (Compose at Runtime):** Workflows whose execution steps are assembled dynamically at runtime rather than statically predefined.
* **Architectural Discipline:** Every primitive added increases cost (tokens and latency), complexity (observability and governance), and risk. Solutions architects must enforce the principle of minimal primitive usage, avoiding heavy abstractions (e.g., Agent Teams) when lighter primitives (e.g., single Tool calls) suffice.

---

### 2. Clear & Simple Explanation

* **The Seven Lego Bricks:** Complex AI systems are constructed by combining seven basic building blocks.
* **Action & Connection:** *Tools* give the model hands to perform actions, while *MCP* acts as a universal adapter allowing multiple apps to access the same tools without rewrite.
* **Execution Controls:** *Hooks* are hardcoded safety rails that run automatically on system events and cannot be ignored by the model. *Skills* are pre-packaged instruction manuals for repeating specific jobs.
* **Parallelism & Coordination:** *Subagents* handle heavy side-tasks in their own separate workspaces so the main conversation doesn't get cluttered. *Agent Teams* collaborate as equals on broad goals, while *Dynamic Workflows* figure out their execution path step-by-step as data arrives.
* **Minimal Primitive Principle:** Reaching for a complex primitive when a simpler one works incurs unnecessary latency, token costs, and maintenance overhead on every request.

---

### 3. Preserve Technical Accuracy

Architectural evaluation requires mapping requirements strictly to the operational capabilities and trade-offs of each primitive:

* **Deterministic Event Execution:** **Hooks** fire on specific lifecycle events to provide unskippable policy enforcement, contrasting with prompt-based instructions which are non-deterministic.
* **Context Isolation & Parallelization:** **Subagents** restrict context window expansion by isolating heavy sub-tasks into dedicated execution contexts, preventing token bloat in the primary reasoning loop.
* **Interoperable Abstraction:** **Model Context Protocol (MCP)** decouples tool server implementation from client entry points, establishing standardized interfaces for enterprise tool ecosystems.
* **Procedural Encapsulation:** **Skills** package versioned execution logic and helper scripts into standardized runtime assets.

---

### 4. Real-World Application

An enterprise cloud ops platform automates IT incident remediation:

* **Connection & Actions:** The core system uses **MCP** to connect Claude to AWS APIs and Jira via standardized **Tools** for restarting microservices and updating tickets.
* **Parallel Log Analysis:** When a high-severity alert fires, the system spawns parallel **Subagents** to parse disparate database and network logs independently, isolating high-volume log tokens from the main orchestration window.
* **Unskippable Governance:** To comply with security policies, deterministic **Hooks** run prior to executing any destructive tool call (e.g., instance reboot), validating IAM permissions in application code before the model call proceeds.
* **Encapsulated SOPs:** Standard Operating Procedures for database failovers are packaged as versioned **Skills**, ensuring repeatable step-by-step execution across incidents.

### 5. Exam Practice

**Question 1**

An enterprise architect is reviewing a design for an internal document summarizer. The development team deployed a multi-agent framework where five peer agents pass document chunks to one another. System benchmarks indicate excessive latency and high token expenditure per request. Which architectural correction best aligns with CCAR-P primitive optimization principles?

A) Replace the multi-agent framework with a single completion call utilizing a single Tool or Subagent for document chunk processing.

B) Migrate the agent framework from direct API calls to an MCP server deployment.

C) Add deterministic Hooks between each peer agent to compress intermediate prompt outputs.

D) Encapsulate the peer agent execution instructions into a versioned Skill asset.

**Question 2**

A regulated financial application must guarantee that an agent never executes a fund transfer exceeding $10,000 without prior compliance validation. The design team placed instructions in the system prompt stating "Do not call transfer_funds if amount > 10000". Why is this design insufficient for CCAR-P compliance, and what primitive should be used instead?

A) System prompts lack version control; the logic must be packaged into a reusable Skill.

B) System prompts are non-deterministic; an unskippable deterministic Hook must intercept tool calls and validate transfer limits in code before execution.

C) System prompts increase context latency; the restriction must be managed via an isolated Subagent.

D) System prompts cannot parse numeric values; the check must be offloaded to an MCP server endpoint.

**Question 3**

An engineering lead needs to expose 15 internal microservice management functions to both a developer terminal interface (`Claude Code`) and a custom web application without maintaining separate tool integration codebases for each interface. Which primitive satisfies this requirement?

A) Agent Teams

B) Dynamic Workflows

C) Model Context Protocol (MCP)

D) Subagents

**Question 4**

A developer wants to analyze four independent 50,000-token log files simultaneously without causing context window exhaustion or high token cross-contamination in the primary reasoning agent. Which primitive pattern should be selected?

A) Spawning four parallel Subagents, each operating in an isolated context window and returning only summarized findings to the primary agent.

B) Wrapping all four log files into a single versioned Skill file loaded in the root prompt.

C) Executing a sequential Dynamic Workflow within a single agent context.

D) Registering an event Hook that streams log files directly into the system prompt.

---

#### Answer & Explanation Key

* **Question 1 Correct Answer:** **A**
*Explanation:* Over-engineering a solution with peer agent teams for a simple task incurs heavy latency and token penalties. The minimal primitive principle dictates using the lightest primitive possible—here, a single completion or isolated subagent call.
* **Question 2 Correct Answer:** **B**
*Explanation:* Model completions are non-deterministic; safety-critical business logic cannot rely solely on system prompts. **Hooks** execute deterministic code on system events, guaranteeing that compliance rules are strictly enforced prior to tool execution.
* **Question 3 Correct Answer:** **C**
*Explanation:* **MCP** provides a standardized protocol for exposing tool sets across multiple Claude entry points, eliminating duplicate tool integration code across client environments.
* **Question 4 Correct Answer:** **A**
*Explanation:* **Subagents** isolate work into separate context windows, enabling parallel processing while keeping raw log tokens out of the primary orchestration window to prevent context bloat and performance degradation.

### Key Technical Terms

* **Tools:** Functions or API bindings that allow the model to take actions or fetch state from external systems.
* **Model Context Protocol (MCP):** An open standard protocol for securely exposing tools and resources to multiple client entry points.
* **Subagents:** Independent model invocations assigned scoped sub-tasks to isolate context or run tasks in parallel.
* **Hooks:** Deterministic code firing on specific system events to enforce unskippable guardrails and business logic.
* **Skills:** Versioned, reusable packages containing instructions and scripts that standardize repeatable execution procedures.
* **Agent Teams:** Coordinated peer agents collaborating on broad, multi-faceted goals.
* **Dynamic Workflows:** Runtime-assembled processing pipelines whose execution paths adapt dynamically based on intermediate results.
