### 1. Summary

The [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) module defines three distinct architectural layers required for every enterprise deployment:

* **Entry Points:** The user- or system-facing wrappers determining access, interaction models, and operational workflows (e.g., **Claude.ai**, **Claude Code**, custom API web/mobile applications).
* **Build-Time Interfaces:** The programmatic abstraction layer that software engineers code against (e.g., direct **API**, **SDKs**, **Model Context Protocol (MCP)**, **Agent SDK**).
* **Delivery Routes:** The infrastructure hosting environments where API traffic terminates, dictating cloud commitments, data residency, and compliance boundaries (e.g., **Anthropic direct**, **AWS Bedrock**, **GCP Vertex AI**, **Microsoft Foundry**).
* **Architectural Failure Mode:** Collapsing these distinct layers (e.g., selecting an engineer-centric entry point like **Claude Code** for non-technical enterprise staff) introduces integration cost, operational friction, and security/governance risks.

---

### 2. Clear & Simple Explanation

* **Three Distinct Decisions:** Every deployment requires choosing who interacts with the system, how developers program it, and where the traffic runs. Blurring these three choices together is the single most common cause of confused architectural reviews.
* **Entry Points (Who and How):** Governs the end-user experience. Software developers need terminal interfaces or IDE integrations, while non-technical business staff require structured web forms or custom application workflows.
* **Build-Time Interfaces (Developer Tools):** Governs how code is written. Engineers use SDKs, APIs, or protocols like MCP to integrate model capabilities into broader application logic.
* **Delivery Routes (Infrastructure & Hosting):** Governs enterprise compliance, cloud billing commitments, and regional data hosting boundaries.
* **Avoiding Layer Collapse:** Never pick a user wrapper before identifying the end user, and never assume that using the same underlying Claude model makes every interface suitable for every user persona.

---

### 3. Preserve Technical Accuracy

Architectural evaluation requires isolating requirements independently across all three platform layers:

* **Entry Point Selection:** Tailors interaction wrappers (**Claude.ai**, **Claude Code**, custom API wrappers) to the target persona, preventing workflow impedance and unauthorized system exposure.
* **Build-Time Interface Abstraction:** Standardizes integration patterns using programmatic contracts (**API**, **SDKs**, **Agent SDK**, **MCP servers**) to isolate application code from model execution details.
* **Delivery Route Infrastructure:** Maps API traffic termination to specific cloud infrastructure providers (**Anthropic direct**, **AWS Bedrock**, **GCP Vertex AI**, **Microsoft Foundry**) to meet enterprise compliance, zero-data-retention (ZDR) requirements, and existing enterprise cloud spend commitments.

### 4. Real-World Application

A global retail bank is building an AI-assisted loan underwriting solution for branch officers:

* **Stakeholder Requirements:** The security team requires all data processing to remain within their existing AWS VPC footprint to satisfy financial regulatory compliance. The engineering team needs standard programmatic integration tools, while branch loan officers require a streamlined, non-technical web interface.
* **Layer Isolation & Architectural Decisions:**
* *Entry Point:* A custom internal Angular web application connected to a backend proxy API wrapper tailored specifically to loan officer workflows (explicitly rejecting developer-focused entry points like **Claude Code** or public **Claude.ai**).
* *Build-Time Interface:* Developers use the **Anthropic Python SDK** combined with **MCP servers** to securely pull customer credit histories from internal databases.
* *Delivery Route:* API traffic terminates on **AWS Bedrock** to leverage existing enterprise discount commitments and enforce strict AWS VPC data residency controls.

### 5. Exam Practice

**Question 1**

An enterprise solution architect is reviewing a proposal for a wealth management platform. The design team suggests deploying **Claude Code** directly to financial advisors so they can query portfolio models via natural language commands in a terminal interface. How should the architect evaluate this proposal according to CCAR-P platform layer principles?

A) Approve the proposal, as Claude Code provides the lowest latency for agentic tool selection.

B) Reject the proposal, because collapsing the entry point layer by assigning a developer CLI interface (**Claude Code**) to non-engineering business staff creates severe operational friction and workflow misalignment.

C) Approve the proposal, provided the delivery route is migrated from Anthropic direct to AWS Bedrock.

D) Reject the proposal, because Claude Code cannot communicate with external Model Context Protocol (MCP) servers.

**Question 2**

A regulated healthcare organization must deploy a Claude-driven diagnostic assistance tool. To satisfy HIPAA data residency and leverage pre-existing cloud credits, all model invocation traffic must remain within the organization's dedicated Google Cloud environment. Which platform layer decision directly addresses this constraint?

A) Selecting a custom API wrapper as the Entry Point.

B) Selecting GCP Vertex AI as the Delivery Route.

C) Selecting the Agent SDK as the Build-Time Interface.

D) Selecting Claude.ai Enterprise as the Entry Point.

**Question 3**

During an architectural review, an engineering lead insists that picking AWS Bedrock automatically determines the user interface and developer SDKs for the entire project. What architectural misconception is occurring?

A) Collapsing the delivery route, build-time interface, and entry point layers into a single decision, ignoring that each layer addresses distinct stakeholders and technical requirements.

B) Failing to implement generator-verifier loops for prompt completions.

C) Misunderstanding that AWS Bedrock only supports single-turn completions and cannot run multi-agent workflows.

D) Over-allocating token budget within the model context window.

**Question 4**

An engineering team is building an automated multi-agent workflow that requires dynamic tool discovery across proprietary microservices. Which option represents the appropriate **Build-Time Interface** choice for this technical requirement?

A) Claude.ai Desktop application wrapper.

B) Model Context Protocol (MCP) and the Anthropic Agent SDK.

C) Microsoft Foundry enterprise infrastructure endpoints.

D) AWS Bedrock VPC Peering route.

---

#### Answer & Explanation Key

* **Question 1 Correct Answer:** **B**
*Explanation:* The proposal collapses platform layers by assigning a developer build-time CLI entry point (**Claude Code**) to non-engineering business staff (financial advisors). Entry points must match the user persona and workflow requirements.
* **Question 2 Correct Answer:** **B**
*Explanation:* Delivery Routes dictate where API traffic terminates and whose infrastructure hosts the model execution. Selecting **GCP Vertex AI** directly satisfies cloud credit commitments and GCP data residency compliance.
* **Question 3 Correct Answer:** **A**
*Explanation:* Entry points, build-time interfaces, and delivery routes are distinct architectural layers. Selecting a delivery route (AWS Bedrock) does not dictate or collapse the entry point (user UI wrapper) or build-time interface (SDKs/APIs).
* **Question 4 Correct Answer:** **B**
*Explanation:* **MCP** and the **Agent SDK** are Build-Time Interfaces designed for engineers to programmatically connect model logic to tools and external data sources. Claude.ai is an entry point, while Microsoft Foundry and AWS Bedrock are delivery routes.

### Key Technical Terms

* **Entry Point:** The front-end user interface or system wrapper through which human users or upstream applications directly interact with Claude (e.g., **Claude.ai**, **Claude Code**, custom API wrappers).
* **Build-Time Interface:** The developer-facing API, SDK, or protocol used by software engineers to programmatically write code against Claude (e.g., **Anthropic SDK**, **Agent SDK**, **MCP**).
* **Delivery Route:** The cloud infrastructure provider and network endpoint where model execution traffic terminates (e.g., **Anthropic Direct**, **AWS Bedrock**, **GCP Vertex AI**, **Microsoft Foundry**).
* **Model Context Protocol (MCP):** An open standard build-time interface for securely connecting LLM applications to external databases, APIs, and tools.
* **Layer Collapse:** The architectural failure mode of confusing or blurring entry points, build-time interfaces, and delivery routes into a single decision.
