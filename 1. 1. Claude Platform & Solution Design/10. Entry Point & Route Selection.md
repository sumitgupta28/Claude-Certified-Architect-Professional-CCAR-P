**1. Summary**

The [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) module details the selection, governance, and architectural integration of entry points, build-time interfaces, delivery routes, and security constraints:

* **Sequential Decision Framework:** Architecting Claude integration requires three sequential decisions: selecting the end-user entry point, choosing the build-time interface, and aligning the Cloud Service Provider (CSP) delivery route.
* **Entry Point Capabilities & Boundaries:** Distinguishes end-user interfaces across user types:
  * *Claude.ai:* Consumer and enterprise tiers (Team/Enterprise featuring SSO, SCIM, audit logs, and HIPAA-ready BAA support).
  * *Claude Code & Cowork:* Specialized agentic entry points for engineering (code editing, terminal execution) and non-engineering desktop file/task automation.


* **Build-Time Interface Layering:**
  * *Direct API & SDKs:* The core interaction layer; SDKs add language-native types and streaming ergonomics over HTTP.
  * *Model Context Protocol (MCP):* An open protocol designed for tool sharing across multiple distinct Claude clients (e.g., Claude.ai, Claude Code, custom web apps) rather than single-product tool calls.
  * *Claude Agent SDK (`@anthropic-ai/claude-agent-sdk`):* Embedded managed runtime executing multi-turn agent loops (iteration, tool execution, termination) directly inside partner applications.


* **Claude Code Customization Architecture:**
  * *Shaping Layers:* Directs agent knowledge and behavior (`CLAUDE.md`, Skills, Subagents, MCP servers).
  * *Governing Layers:* Enforces non-bypassable security controls (Hooks, permission modes such as `acceptEdits`, `Plan mode`, `Auto mode`, `dontAsk`, `bypassPermissions`, and workspace sandboxing).




* **CSP Delivery Routes:** Evaluates deployment endpoints across Anthropic first-party, AWS Bedrock, GCP Vertex AI, and Microsoft Foundry. Model capability remains identical across routes, but CSP routes leverage existing enterprise cloud contracts, IAM roles, and regional data residency at the trade-off of a multi-week feature release lag.
* **Regulated-Industry Governance:** Mandatory constraints (HIPAA, GDPR, attorney-client privilege) rule out entry points prior to technical preferences. HIPAA requires configuration-specific BAAs (excluding non-eligible beta features), and privilege review requires firm-owned audit logging via API/SDK gateways.

### Key Architectural Principle

In production enterprise architectures, always wrap user-supplied data inside clear XML boundary tags (e.g., `<ticket>`, `<receipt_text>`, `<contract_clause>`). This isolates untrusted user text from system instructions, preventing prompt injection attempts from altering system behavior.

## Key Architectural Concepts & Tradeoffs

| Category | Option / Tier | Core Use Case & Target Audience | Key Architectural Tradeoff |
| --- | --- | --- | --- |
| **Entry Points** | Claude.ai (Free, Pro, Max, Team, Enterprise) | Applied AI users / knowledge workers using chat for analysis, drafting, research. | Zero build cost vs. zero custom embeddability. Enterprise tier adds SCIM, HIPAA readiness, and audit logs. |
| **Entry Points** | Claude Code | Software engineers building features, refactoring code, and operating in CLI/IDE/web environments. | Purpose-built for code engineering; unsuitable as an end-user UI for non-engineering workflows. |
| **Entry Points** | Claude Cowork | Non-technical ops/admin personnel automating local machine files and applications. | Powerful local system action execution vs. higher human supervision and permission scoping overhead. |
| **Build-Time Interfaces** | API & Native SDKs | Single request-response interactions or custom-built orchestration logic. | SDK adds language-native ergonomics; raw HTTP API is reserved for freshly released features not yet in SDKs. |
| **Build-Time Interfaces** | Model Context Protocol (MCP) | Exposing reusable tools to multiple heterogeneous AI clients simultaneously. | Protocol layer for broad tool reusability across clients, not a replacement for single-request tool calling. |
| **Build-Time Interfaces** | Claude Agent SDK | Running autonomous multi-turn agent loops embedded directly inside custom applications. | Managed loop runtime (handles tool calls and stop conditions) vs. manual state management. |
| **Delivery Routes** | Direct Anthropic API | Teams wanting immediate access to new model features with no preference for a specific cloud vendor. | Immediate feature availability vs. requiring separate billing/procurement outside existing cloud contracts. |
| **Delivery Routes** | CSP Routes (AWS Bedrock, GCP Vertex AI, Azure Foundry) | Enterprise deployments leveraging existing cloud contracts, IAM identity, and regional boundaries. | Aligns with existing enterprise cloud spend commitments; feature releases may lag the direct API by weeks. |

**2. Clear & Simple Explanation**

* **Three-Step Order:** Always pick *who* uses the tool (entry point) first, *how* your code calls it (interface) second, and *where* the cloud traffic lands (delivery route) third.
* **Choosing the Right Interface:** Use the standard Anthropic SDK for basic single-turn calls. Use MCP when a tool must be shared across different apps (like Claude.ai and terminal scripts). Use the Agent SDK to embed an autonomous multi-turn agent loop into your own web application backend.
* **Shaping vs. Governing:** Shaping tools (`CLAUDE.md`, Skills) teach the agent how to do its job well. Governing tools (Hooks, sandboxing, permission modes) act as hard security walls preventing unauthorized system access.
* **Cloud Route Selection:** Model reasoning power is identical whether using Direct API, AWS Bedrock, GCP Vertex AI, or Azure Foundry. Choose based on existing corporate cloud spend commitments and security credentials.

**3. Real-World Application**

**Scenario: HIPAA-Compliant Medical Claims & Billing Assistant**
A health insurance provider builds an agentic workflow to review patient claims, query medical history databases, and output billing codes within an AWS cloud infrastructure.

**Architectural Implementation:**
  * **Entry Point & Route:** Rejects consumer Claude.ai to comply with HIPAA. The team selects an API integration routed through **AWS Bedrock** to draw down against existing AWS Enterprise Discount Program (EDP) commitments and enforce IAM role-based access control under a signed BAA.
  * **Build-Time Interfaces:** The core backend uses the **Claude Agent SDK** to run an autonomous, multi-turn review loop inside an isolated container. To allow developer tools in Claude Code and internal auditors on Claude.ai Enterprise to access the same medical terminology lookup tool, the service is packaged as an **MCP server**.
  * **Governance Layers:** System architects deploy **governing layers** (Hooks blocking database write operations and network egress rules) to prevent unauthorized PHI modification. **Shaping layers** (`CLAUDE.md` and custom versioned Skills via `/v1/skills`) guide billing code accuracy.

**4. Exam Practice**

* **Question 1**

A solution architect at a healthcare firm must deploy Claude to process protected health information (PHI). The organization holds a Business Associate Agreement (BAA) and developers want to utilize a newly released experimental tool-calling API feature. Which delivery route and configuration strategy should the architect mandate?

* A. Direct Anthropic API on a consumer Claude.ai Pro subscription with experimental flags enabled.
* B. Direct Anthropic API or a supported CSP delivery route using a BAA-covered enterprise configuration, excluding the experimental feature from PHI workflows unless explicitly declared BAA-eligible.
* C. AWS Bedrock using unvalidated beta endpoints, as all CSP endpoints inherit automatic BAA coverage.
* D. Microsoft Foundry using consumer-grade hosting without verifying individual model eligibility.


* **Question 2**

An engineering organization wants to expose a single internal database search tool to developers using Claude Code, non-technical staff using Claude.ai Enterprise, and a custom internal web dashboard. Which build-time interface pattern should be implemented?

* A. Direct API tool calls configured separately inside each client application's system prompt.
* B. A centralized Model Context Protocol (MCP) server exposing the tool to all three client entry points.
* C. An Anthropic Python SDK script running inside an isolated AWS Lambda function.
* D. A Claude Agent SDK managed loop deployed as a standalone CLI tool.


* **Question 3**
 A security lead mandates that a Claude Code automation agent running in CI/CD must never execute unapproved shell commands or bypass safety gates, regardless of prompt instructions. How should the system architect enforce this constraint?

* A. Add explicit negative prompt rules in `CLAUDE.md` warning the agent against running shell commands.
* B. Implement governing layers using Hooks and `dontAsk` permission mode within a sandboxed execution environment.
* C. Define a custom Subagent with a high sampling temperature to evaluate command safety dynamically.
* D. Convert all execution tasks into zero-shot prompt templates using the Anthropic SDK.


* **Question 4**
A company with an active AWS Enterprise Discount Program (EDP) needs to integrate Claude into its internal microservices while maintaining strict IAM role access controls. However, the development team requires immediate access to a feature launched today on the Anthropic Direct API. What is the primary architectural trade-off the architect must present to stakeholders?

* A. AWS Bedrock provides superior model intelligence compared to the Direct Anthropic API, but costs 20% more.
* B. Routing through AWS Bedrock leverages existing EDP spend and IAM infrastructure, but CSP routes typically lag first-party API feature releases by weeks.
* C. The Direct Anthropic API automatically syncs IAM credentials, but context window token limits are reduced by half on CSP routes.
* D. AWS Bedrock disables prompt caching, whereas the Direct Anthropic API requires custom model fine-tuning.



---

**Answers and Explanations**

* **Question 1 Correct Answer: B**
* **Explanation:** BAA coverage applies strictly to specific enterprise configurations, and beta or experimental features are generally excluded from BAA coverage unless explicitly declared eligible by Anthropic.


* **Question 2 Correct Answer: B**
* **Explanation:** Model Context Protocol (MCP) is specifically designed as an open tool-sharing protocol across multiple distinct Claude clients (Claude.ai, Claude Code, and custom applications).


* **Question 3 Correct Answer: B**
* **Explanation:** Security and execution controls must be enforced by governing layers (Hooks, permission modes like `dontAsk`, sandboxing), which provide deterministic code-level guarantees that prompt instructions (`CLAUDE.md`) cannot guarantee.


* **Question 4 Correct Answer: B**
* **Explanation:** Model reasoning capability is identical across all delivery routes. However, CSP routes (Bedrock, Vertex, Foundry) allow organizations to draw down existing cloud commitments and use IAM roles, at the trade-off of a multi-week lag for newly launched first-party API features.

**Key Technical Terms**

* **Entry Point:** The wrapper or interface (Claude.ai, Claude Code, Direct API) that determines user access, tool reach, and integration effort.
* **Build-Time Interface:** The programmatic development layer (Direct API, SDKs, MCP, Agent SDK) used to integrate Claude into client application code.
* **Model Context Protocol (MCP):** An open standard for exposing and discovering reusable tools, prompts, and resources across multiple independent Claude clients.
* **Claude Agent SDK:** A managed runtime (`@anthropic-ai/claude-agent-sdk`) that embeds an autonomous multi-turn execution loop into custom application codebases.
* **Shaping Layers:** Customization configurations (`CLAUDE.md`, Skills, Subagents, MCP) that direct what an agent knows and how it formats tasks.
* **Governing Layers:** Security and control mechanisms (Hooks, permission boundaries, sandboxing) that deterministically restrict what systems or actions an agent can execute.
* **CSP Delivery Route:** The underlying cloud provider endpoint (Direct Anthropic API, AWS Bedrock, GCP Vertex AI, Microsoft Foundry) where API traffic terminates.
* **Business Associate Agreement (BAA):** A legally binding contract required under HIPAA ensuring appropriate administrative and physical safeguards for Protected Health Information (PHI).
* **Permission Boundaries:** Explicit permission modes in Claude Code (e.g., `acceptEdits`, `dontAsk`, `Plan mode`, `bypassPermissions`) controlling automated execution privileges.
* **Hooks:** Deterministic event scripts triggered on agent lifecycle events (e.g., before/after tool execution) that enforce non-bypassable constraints.
