### 1. Summary

The [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) course outlines the decision framework for composing AI primitives into three primary structural patterns: **Augmented LLMs**, **Workflows**, and **Agents**.


* **Three Structural Involvement Patterns:**
  * **Augmented LLM:** Sits in the high-predictability, low-autonomy quadrant. Consists of a single model invocation (enhanced with tool use, retrieval, or extended thinking) where outer application code controls the execution flow and no branching occurs based on model outputs.
  * **Workflow:** Occupies the middle band of predictability and autonomy. Application code defines the overall control flow, but bounded model judgment is embedded inside discrete steps.
  * **Agent:** Sits in the high-autonomy, low-predictability quadrant. The model dynamically determines its own execution trajectory across multi-turn loops (e.g., long-horizon code exploration). Because the model trajectory *is* the control flow, non-deterministic failures concentrate here without code boundaries for standard programmatic guards.

* **Canonical Workflow Sub-Patterns:**
  * **Chaining:** Sequential, linear execution where Step $n$'s output becomes Step $n+1$'s input (e.g., extract $\rightarrow$ classify $\rightarrow$ summarize).
  * **Routing:** An initial classifier directs inputs down distinct specialized handling paths based on input type.
  * **Parallelization:** Concurrent model executions split by **Sectioning** (processing independent document parts simultaneously) or **Voting** (aggregating parallel outputs for consensus).
  * **Evaluator-Optimizer:** An iterative loop where a generator LLM produces an artifact and an evaluator LLM critiques it against explicit rubrics or schemas until quality criteria or retry limits are satisfied.

* **Five-Factor Decision Framework:** Architects evaluate patterns sequentially across:
  1. **Predictability:** Can the steps be enumerated in advance?
  2. **Error Cost:** What is the business impact of an unhedged failure?
  3. **Observability:** Can operational teams trace and reconstruct decision trajectories?
  4. **Latency Budget:** What is the user-visible completion SLA?
  5. **Cost:** What is the cumulative per-request token usage at scale?

|Feature / Factor	|Augmented LLM	|Workflow	|Agent |
|---  |---	|---	|--- | 
|Control Flow	| Code-driven (single call) |	Code-driven (multi-step graph)	| Model-driven (dynamic loop)|
|Error Cost	 |Low–Medium (bounded to single call)	| Low (isolated step guardrails) |	High (compounding across turns)|
|Observability |	Simple to log; standard tools	| Standard trace/step logging	| Open-ended trajectory transcript|
|Token Cost & Latency	| Lowest cost; fastest execution |	Predictable & additive	| Variable; high context/turn overhead|
|Primary Risk	| Simple prompt failures	| Individual step failures |	Unpredictable decisions or logic loops|



* **Optimization Progression over Fine-Tuning:** Fine-tuning should be treated as a last resort.
  Solution design must follow a strict optimization sequence:
 ``` 
  `Optimize Prompt` --> `Add Tools / RAG` --> `Evaluator-Optimizer Workflow` --> `Fine-Tuning`.
```
*Fine-tuning is reserved strictly for high-volume inference cost constraints, sub-second latency needs on smaller specialized models, or rigid output format compliance.*
  * **Skills-Based Architecture & Trade-Offs:**
    * **Skills-Based Architecture:** Packages reusable procedures, instructions, and scripts into versioned, governed units distributed across teams.
    * **Architectural Trade-Offs:** Cost is driven by context accumulation rather than pattern labels. Agent risk represents an organization's **liability surface**—broader tool access expands potential failure modes.

### 2. Clear & Simple Explanation

* **Augmented LLM = A smart single function call:** You send data to Claude once, Claude returns an answer or tool call, and your regular application code takes over. The AI never decides what step happens next.
* **Workflow = An automated assembly line:** Your code manages the conveyor belt and dictates every step in order. However, at individual stations along the belt, you use Claude to perform tasks requiring human-like judgment (like summarizing a paragraph or grading text).
* **Agent = A contractor given a goal:** You give Claude a goal and a toolbox, and Claude decides step-by-step what actions to take, what files to read, and when the job is done. This is powerful for open-ended tasks, but harder to predict and debug.

* **Workflow Sub-Patterns Explained:**
  * *Chaining:* A relay race where each runner passes the baton to the next (e.g., Read Document $\rightarrow$ Find Risks $\rightarrow$ Write Report).
  * *Routing:* A triage nurse directing arriving patients to emergency, pediatrics, or radiology.
  * *Parallelization:* A team of analysts reading different chapters of a thick report at the same time to save time.
  * *Evaluator-Optimizer:* An author writing a draft and submitting it to an editor, who redlines it and sends it back until it meets publication standards.


* **Don't jump straight to Fine-Tuning:** If Claude isn't giving the right output, fix the prompt first. If that fails, add tools or search context. If that still fails, build an evaluator-optimizer loop. Only consider fine-tuning if you have massive request volumes or strict latency demands that require a tiny model.

### 3. Real-World Application

**Scenario: Automated Enterprise Vendor Due Diligence & Contract Risk Platform**

* **Business Problem:** An enterprise procurement team processes thousands of vendor agreements annually. Manual legal reviews take weeks, while relying on a single open-ended agent causes hallucinations on liability caps and unpredictable API costs.
* **Architectural Solution using Pattern Selection:**

```
                    ┌─────────────────────────┐
                    │  Inbound Contract PDF   │
                    └────────────┬────────────┘
                                 │
                                 ▼
                     ┌───────────────────────┐
                     │    ROUTING PATTERN    │
                     │ (Claude 3.5 Haiku)    │
                     └───────────┬───────────┘
                                 │
            ┌────────────────────┴────────────────────┐
            │ Standard Legal Contract                 │ Complex Non-Standard
            ▼                                         ▼
┌───────────────────────────────┐         ┌───────────────────────────────┐
│    PARALLELIZATION PATTERN    │         │          AGENT LOOP           │
│   (Sectioning across LLMs)    │         │  (Autonomous Legal Research)  │
└───────────────┬───────────────┘         └───────────────┬───────────────┘
                │                                         │
                ▼                                         │
┌───────────────────────────────┐                         │
│     EVALUATOR-OPTIMIZER       │                         │
│   (Draft vs. Risk Rubric)     │                         │
└───────────────┬───────────────┘                         │
                │                                         │
                └────────────────────┬────────────────────┘
                                     │
                                     ▼
                        ┌─────────────────────────┐
                        │   Human Legal Review    │
                        └─────────────────────────┘

```

1. **Routing Pattern:** Inbound vendor contract PDFs are received by a fast, low-cost classifier (**Claude 3.5 Haiku**) that routes standard vendor agreements to a deterministic workflow, while routing non-standard custom agreements to an agentic queue.
2. **Parallelization Pattern (Sectioning):** Standard agreements are split into four independent sections (Data Privacy, Liability Caps, IP Rights, Termination Rules). Four parallel model calls process these sections simultaneously, reducing processing latency from minutes to seconds.
3. **Evaluator-Optimizer Pattern:** A generator LLM drafts proposed redlines for flagged liability clauses. A second evaluator LLM grades the redlines against corporate policy rubrics and JSON schema rules. If the redline fails the policy rubric, it loops back for revision before human sign-off.
4. **Agent Pattern (Selective Escalation):** For complex non-standard agreements, a specialized legal research **Agent** with scoped search tools autonomously explores internal contract repositories to identify historical precedents.

### 4. Exam Practice

**Question 1**

An enterprise development team is building a medical diagnostic assistant. Regulatory policy dictates that the system's execution path must be 100% audit-traceable, with zero risk of unmonitored decision branching. However, individual processing steps (such as extracting patient history from unstructured clinical notes) require natural language intelligence. Which architectural pattern must the solution architect select?

A. Agent pattern using open-ended tool loops.

B. Fine-tuned specialized model operating without system prompts.

C. Workflow pattern with deterministic application control flow surrounding bounded LLM calls.

D. Multi-agent swarm with dynamic peer-to-peer delegation.

**Question 2**

A financial services company processes 50-page earnings reports. To minimize end-to-end processing latency for end users, the architect decides to extract key financial metrics from all ten chapters simultaneously rather than processing the document sequentially. Which workflow sub-pattern directly addresses this requirement?

A. Chaining

B. Routing

C. Evaluator-Optimizer

D. Parallelization via Sectioning

**Question 3**

During a design review, a lead developer proposes fine-tuning Claude 3.5 Sonnet because the model occasionally fails to output valid JSON during complex data extraction tasks. According to Anthropic architectural best practices, what should the CCAR-P architect recommend as the correct sequence of remediation steps?

A. Immediately initiate model fine-tuning on a dataset of 10,000 JSON examples.

B. Optimize system prompts and enforce structured outputs/JSON Schema $\rightarrow$ Add retrieval/tool validation $\rightarrow$ Implement an Evaluator-Optimizer loop $\rightarrow$ Consider fine-tuning only as a last resort.

C. Replace Claude 3.5 Sonnet with an autonomous agent loop using extended thinking.

D. Switch from direct API hosting to an unmanaged open-source model.

**Question 4**

A developer designs an customer support agent that autonomously issues account refunds, updates billing databases, and sends emails. During testing, the agent occasionally enters multi-turn loops that trigger invalid database updates and burn through token budgets. What fundamental architectural flaw caused this issue?

A. The architect failed to fine-tune the model before enabling tool access.

B. The agent was deployed without a RAG vector database connection.

C. The system granted high model autonomy to an un-bounded agent loop without intermediate code guards, expanding the risk liability surface.

D. The system used Claude 3.5 Haiku instead of Claude 3 Opus for tool execution.

---

#### Answer Key & Explanations

* **Question 1 Answer: C**
* *Explanation:* Workflows provide deterministic control flow where application code dictates the execution path, ensuring high observability and auditability while leveraging bounded model judgment inside specific steps.


* **Question 2 Answer: D**
* *Explanation:* Parallelization via Sectioning splits large independent document chunks (e.g., chapters) across concurrent model calls, significantly reducing Time to First Token (TTFT) and overall latency.


* **Question 3 Answer: B**
* *Explanation:* Anthropic guidelines mandate a strict progression: optimize prompts and structured outputs first, introduce tools/retrieval or evaluator-optimizer loops next, and treat fine-tuning as a last resort.


* **Question 4 Answer: C**
* *Explanation:* Agents operate with high model autonomy and low predictability. Unbounded agent trajectories without strict turn budgets, code boundaries, or narrow tool scoping expand the system's liability surface and lead to non-deterministic failure modes.

### Key Technical Terms

* **Augmented LLM:** A single model invocation wrapped in application code that may include tools, retrieval, or extended thinking, but where control flow never branches based on model output.
* **Workflow:** An architectural pattern where application code controls the overall sequence and logic, embedding bounded model judgment within specific steps.
* **Agent:** An architectural pattern where the model dynamically controls its own trajectory, execution steps, and tool calls across multi-turn loops to achieve an open-ended goal.
* **Chaining:** A sequential workflow sub-pattern where the output of one step serves directly as the input to the next.
* **Routing:** A workflow sub-pattern that uses a classifier to direct inputs down distinct specialized downstream processing paths.
* **Parallelization (Sectioning / Voting):** A workflow sub-pattern that runs concurrent model calls, either dividing a task into independent streams (sectioning) or generating multiple candidate outputs for consensus evaluation (voting).
* **Evaluator-Optimizer:** An iterative workflow loop where a generator LLM produces an output and an evaluator LLM critiques it against defined rubrics until quality standards are met.
* **Predictability vs. Model Autonomy:** The two core design axes used to map LLM involvement based on execution certainty versus model decision authority.
* **Observability:** The degree to which operational teams can trace, log, and reconstruct the decision-making trajectory of an AI system.
* **Latency Budget:** The maximum allowable user-visible time window for a system to complete a request.
* **Skills-Based Architecture:** A design approach that packages procedures, instructions, and scripts into versioned, governed, and reusable technical units across an enterprise.
* **Liability Surface:** The total potential operational, legal, and financial risk exposed by an agent's autonomous tool permissions and decision authority.
