### 1. Summary

The [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) module details the selection, calibration, and governance of prompt engineering techniques across model tiers:

* **Technique Selection by Task Complexity:** Establishes a minimal-scaffolding progression path to optimize performance while controlling latency and costs:
* **Zero-shot:** Instruction-only prompts without examples. Serves as the primary default for bounded, well-specified tasks (e.g., ticket categorization, simple summarization).
* **Few-shot:** Includes a small set of input/output exemplars. Applied when desired formatting, layout edge cases, or subjective business judgment are easier to demonstrate than describe in natural language (e.g., parsing irregular receipts).
* **Chain-of-thought:** Explicitly prompts the model to generate step-by-step reasoning before producing the final answer. Reserved for multi-step conditional logic, arithmetic reasoning, or interdependent policy evaluation where intermediate paths dictate correctness.


* **Model-Tier Behavioral Calibration & Eval Gating:** Model tiers (e.g., Opus vs. Sonnet vs. Haiku) exhibit different baseline capabilities. Higher-tier models require less scaffolding (fewer exemplars, lighter instructions), whereas lower-tier models require additional guidance. Because prompt performance is strictly bound to model behavior, swapping models is a production deployment event that must be gated by regression evaluation suites.
* **Prompt Bias Mitigation & Architectural Trade-offs:**
  * *Cost:* Applying heavy techniques like chain-of-thought to straightforward tasks imposes a permanent token and latency tax.
  * *Complexity:* Maintenance overhead grows with few-shot exemplars; outdated or unbalanced examples cause silent prompt drift.
  * *Risk:* Unbalanced exemplars or leading prompt instructions introduce hidden bias that degrades aggregate system accuracy.

### 2. Clear & Simple Explanation

* **Start Light to Save Money and Time:** Always test zero-shot instructions first. Only add input/output examples (few-shot) if the model struggles with complex formatting, and only ask for step-by-step thinking (chain-of-thought) if the task involves multi-step logic.
* **More Capable Models Need Less Hand-Holding:** Powerful models understand complex directions with fewer examples. If you upgrade or downgrade your model tier, re-test your prompts—what worked for one tier may be redundant or insufficient for another.
* **Examples Can Silently Corrupt Decisions:** If your few-shot examples only show one type of scenario (e.g., approving claims), the model will lean toward approving claims in production. Keep examples balanced and neutrally worded.
* **Prompt-Model Pairing is Production Code:** A prompt and the specific Claude model version it calls function as a single unit. You cannot change the model underneath without running an evaluation suite to verify performance.

### 3. Real-World Application

**Scenario: Enterprise Insurance Claims Processing & Fraud Triage System**
An enterprise insurance solution routes incoming policyholder claims through an automated AI pipeline to parse documentation, verify policy terms, and flag potential fraud.

* **Architectural Implementation:**
* **Stage 1 (Document Data Extraction - Few-shot):** Incoming receipts and damage reports vary widely in layout. The pipeline uses a **few-shot** prompt with 3 diverse exemplar pairs to reliably extract structured JSON fields (`claimant_id`, `loss_amount`, `vendor_tax_id`) without layout failure.
* **Stage 2 (Triage Categorization - Zero-shot):** Claims are categorized into standard departments (*Auto, Property, Liability, Fraud Risk*) using a **zero-shot** prompt, as the categories are explicitly defined and well-handled without additional token overhead.
* **Stage 3 (Liability & Policy Evaluation - Chain-of-thought):** Complex claims involving multiple interacting policy exclusions (e.g., flood vs. windstorm deductibles across overlapping riders) use **chain-of-thought** prompting to force intermediate reasoning steps before declaring coverage approval or denial.
* **Model Swap & Governance:** When migrating the Stage 2 triage agent from Sonnet to Haiku to reduce API costs, the architecture team runs a 500-claim evaluation suite. They discover Haiku requires 2 few-shot exemplars to match Sonnet's zero-shot accuracy, balancing token cost savings against slightly higher prompt token usage.

### Key Technical Terms

* **Zero-shot Prompting:** An instruction-only prompting technique without input/output exemplars, used as the default baseline for well-defined tasks.
* **Few-shot Prompting:** A technique that includes exemplar input/output pairs inside the prompt to demonstrate formatting, structure, or edge-case handling.
* **Chain-of-thought (CoT) Prompting:** A technique that explicitly instructs the model to generate intermediate step-by-step reasoning before providing the final answer.
* **Prompt Scaffolding:** The surrounding instructions, exemplars, and structural formatting added to a prompt to guide model output accuracy.
* **Prompt Bias:** Systematic skew or drift in model outputs caused by unbalanced exemplars, leading phrasing, or implicit assumptions in the prompt.
* **Evaluation-Gated Release (Eval Gating):** The practice of validating prompt and model changes against a benchmark test suite before production deployment.
* **Prompt-Model Pairing:** The architectural coupling of a specific prompt asset with a specific model tier/version, treated as a single version-controlled deployment artifact.
* **Token Tax:** The financial and latency cost incurred by generating unnecessary prompt or reasoning tokens across API calls.
