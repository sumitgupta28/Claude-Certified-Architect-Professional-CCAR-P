### 1. Summary

This module from [Claude Platform & Solution Design](https://anthropic-partners.skilljar.com/path/claude-certified-architect-professional/claude-platform-solution-design/486647/scorm/2gvs1pi0tq0sq) details key architectural decisions across model selection, context strategy, extended thinking, and evaluation gating for production systems:

| Architectural Concept | Primary Function | Management & Access | Key Takeaway |
| --- | --- | --- | --- |
| **Context Window** | Serves as the active attention space for model reasoning during a single call | Engine-level (resets automatically between calls unless managed) | Content outside the window does not exist to the model |
| **Retrieval** | Fetches relevant external knowledge at query time from an unmemorized corpus | Search / Vector Store (pulled dynamically) | Augments the context window; the model only sees what is surfaced |
| **Persistent Application State** | Stores authoritative transactional data (e.g., order status, user records) | Application backend (owned by system, not model) | Model has no native access and must use tool calls to retrieve data |
| **Summaries & Memory Layers** | Maintains continuity and context across multi-turn sessions | Application logic (stored and passed back in by system) | Continuity is an application design choice, not a native model capability |


* **Architectural Boundaries:** Distinguishes *context window* (active attention space), *retrieval* (fetched external data), *persistent application state* (system-owned data accessed via tools), and *summaries/memory layers* (application-managed multi-turn continuity).
  
* **Model Selection Framework:** Establishes Sonnet as the default starting baseline. Upgrades to Opus are reserved for complex reasoning, research synthesis, or advanced coding when Sonnet fails quality targets. Downgrades to Haiku require evaluation proof that cost/latency optimizations retain required accuracy.
  
* **Context Window Sizing:** Avoids the *working-memory cliff* by planning token budgets for system prompts, history growth, retrieved chunks, tool outputs, and growth margins rather than budgeting to the absolute token ceiling.
  
* **Hybrid Context Strategy:** Layers *monolithic prefixes* (leveraging prompt caching), *progressive state* (recent interactions), *just-in-time retrieval (RAG)* (external queries), and *compaction* (periodic summarization) to maintain continuity efficiently.

* **Extended Thinking & Controls:** Controls **reasoning depth on Claude 4.6+ and Claude Sonnet 5 via adaptive thinking using the `effort` parameter**. Legacy manual **`budget_tokens` is deprecated on 4.6 and causes a 400 error on Sonnet 5.** Extended thinking should only be enabled when evaluations confirm an accuracy gain that justifies output token costs and latency.
  
* **Eval-Gated Model Deployments:** Requires setting strict rollback criteria *before* running evaluation suites. Uses stratified test sets to spot category-specific regressions and implement hybrid model routing when downgrading models across varied tasks.

### 2. Clear & Simple Explanation

* **Default to Middle Tier:** Start with Sonnet for standard tasks. Move up to Opus only if testing proves Sonnet lacks required reasoning power; move down to Haiku only if testing shows performance stays high enough for simpler tasks.
  
* **Context Token Limits:** Context windows have hard limits. If you fill them up completely, performance degrades rapidly (the working-memory cliff). Combine caching for static prompts, RAG for retrieving missing facts, and compaction to compress long conversation histories.
  
* **Thinking Overhead:** Extended thinking adds cost and latency. Measure baseline accuracy without extended thinking first, and enable adaptive thinking (`effort`) only if test data proves it directly fixes accuracy gaps.
  
* **Pre-Set Rollback Criteria:** Always define pass/fail thresholds *before* running evaluations on new models. If a cheaper model fails on specific complex edge cases, route only those hard cases to a larger model while keeping simple cases on the cheaper model.

### 3. Real-World Application

**Scenario: Autonomous Code Refactoring & Bug Resolution Agent**
An enterprise developer tool uses an AI agent to inspect code repositories, process multi-turn developer instructions, execute test suites, and fix code bugs.

* **Architecture Implementation:**
  * **Model Routing:** A lightweight edge classifier routes **standard syntax edits to Haiku**, **_core pull requests to Sonnet_**, and **complex architectural refactoring to Opus**.
  * **Context Management:**
   - Repository style guides load as a monolithic prefix using prompt caching.
   - Active debugging steps use progressive context,
   - while unindexed files rely on just-in-time RAG.
   - When turn context exceeds 50k tokens, compaction summarizes previous test runs into key findings while discarding raw terminal outputs.
     
  * **Adaptive Thinking:** Adaptive thinking (`effort: high`) triggers dynamically only after a unit test fails, providing extra reasoning capacity for root-cause diagnosis without slowing down initial generation steps.
    
  * **Eval Gating:** Prior to deployment, an evaluation set tests 300 historical PRs. When Haiku drops below 0.85 accuracy on concurrency bugs, the team configures hybrid routing to direct concurrent code modules to Sonnet while routing basic modules to Haiku.

### Key Technical Terms

* **Context Window:** The model's active token attention limit during a single API request.
* **Retrieval (RAG):** Fetching external data chunks at query time to augment context without loading entire datasets.
* **Persistent Application State:** System data (databases, user records) managed outside the model and accessed via tool calls.
* **Compaction:** Periodically summarizing accumulated context to conserve token budget while preserving decision history.
* **Progressive Context Strategy:** Dynamically passing only the specific context and tool outputs required for the immediate next turn.
* **Monolithic Context Strategy:** Passing all system prompts, background files, and full interaction history in every single API call.
* **Adaptive Thinking (`effort` parameter):** The parameter used to adjust reasoning depth in modern Claude models (e.g., Sonnet 5), replacing deprecated `budget_tokens`.
* **Working-Memory Cliff:** The abrupt degradation of model output quality when context token usage approaches maximum capacity.
* **Eval-Gated Deployment:** Defining pass/fail thresholds on representative test sets *before* evaluating and deploying model version changes.
